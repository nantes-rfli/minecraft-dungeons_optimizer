# Artifact Formal Value / Relation Foundation Design Audit

## 日本語要約

基準は GitHub `main` の `6faa63442319c0569d684a55646997beac6cc0ff`。Formal Identity 済み Artifact 23件はすべて、`applicationScope.packagePath` と Horizontal / Structural の選択 package が一意に一致した。Raw 候補 status は exact 8件、provisional 15件であり、後者は Formal Identity の阻害理由ではない。

Value の全 CDO closure には、domain ごとに追跡可能な leaf fact 250件、数値・真偽値 fact 46件がある。ただし共通の Duration / TickInterval / LoopInterval / Heal 値は成立しない。base cooldown は既知0件、parser-boundary 5件、not-observed 18件で、開始時点・実効挙動も不明。現行 Value v2 に Artifact lane はなく、すぐに全23件を population することはできない。分類は **D: 3件の domain 固有 count / multiplier に限る狭い typed foundation**。候補は Corrupted Seeds の TargetCount、Enchanted Grass の IncreasedMaxHealthMultiplier、Vexing Chant の PetAmountCap とする。

Relation は root `Effect` が10件、`ItemActorClass` が11件、`TomeActorClass` が0件。最初に実装する wave は **Effect scope Relation 10件**（Death Cap Mushroom の既存1件を含み、新規9件）。現行 `effect` kind と `{domainId, scopeRef:"source"}` を使えるが、Armor 用 GearActor 処理をそのまま流用せず、source / target を厳密照合する共通 scope adapter と Artifact Effect policy が必要。ItemActorClass は新しい semantic kind の設計を先に行う。cooldown、実効 duration / damage / healing は未観測・parser/native 境界を保ち、推測で値を埋めない。

監査文書・census・再現スクリプトのみを追加し、production code、Formal artifact population、Raw、PR は変更しない。以下の表と JSON census に23件全件の source role、traversal route、property / edge、target、locator、可用性を記録した。

## Basis and outcome

It does not populate Formal Value/Relation or change production behavior. Regenerate it with `python3 scripts/audit-artifact-formal-foundation-design.py --output docs/artifact_formal_value_relation_foundation_census.json`.

The first implementation wave is **root `Effect` scope Relation for 10 Artifact domains** (9 additional projections; Death Cap Mushroom already exists). This is the only broad family whose target and Formal semantic are both established by the current source. No Artifact Value population is recommended in that wave.

### Cooldown boundary

The committed Horizontal `artifactCooldown` partition is reproduced from the exact 23 selected roots: **base cooldown 0 static-known, 0 relation-traversal-known, 5 parser-boundary, 18 not-observed**. Parser-boundary domains: `corrupted-pumpkin`, `fishing-rod`, `light-feather`, `shock-powder`, `totem-of-casting`. Cooldown timer start semantics and effective cooldown remain Blueprint non-CDO / native execution unknown for all 23. `SharedPassiveCooldown` at Shadow Shifter (0.5) and Spinblade (explicit 0), `PercentageOfTotalCooldownRefunded` at Shadow Shifter, and `CoolDownForEachPetDeath` at Vexing Chant are **different serialized concepts**; none is base cooldown. The explicit Spinblade zero must stay attached to that passive property, never fill the missing base cooldown. `src/data/artifacts.ts`, catalog text, and community values are not Formal source inputs.

### Value contract decision — D: narrow typed foundation only

`semantic.artifact` is absent from `FormalValueAvailabilityArtifact`; the generator initializes only `melee` and `ranged`. `collectSemanticOccurrences`, child-coverage validation, mapping IDs, audits, integration category maps/counts, and fixtures all enumerate those lanes. Data Browser consumers read category-specific v2 shapes. A JSON key alone would be silently unvalidated. A v2 additive extension is feasible **only after** the type, generator, source reader, mapping registry, occurrence enumeration, evidence/projection audit, integration audit, fixtures, and any consumer type expectations all recognize a narrow Artifact lane. No v3 migration is required for the three independent scope values below because the existing v2 projection/evidence/availability contract can express them; changing existing meanings would require a separate migration.

Proposed `FormalArtifactConfiguredValues` (three domain-specific optional fields, no general `Damage`/`Duration` bag):

| Formal field | domain coverage | meaning and Raw property | role / Raw type / unit | occurrence and mapping ID | relation dependency | availability |
| --- | --- | --- | --- | --- | --- | --- |
| configuredTargetCount | corrupted-seeds (1) | configured target count; `TargetCount` | root / IntProperty / count | `{domainId, scopeRef:"source"}`; `corrupted-seeds:configured-target-count@1` | none | known 1; other domains not-applicable |
| configuredIncreasedMaxHealthMultiplier | enchanted-grass (1) | configured maximum-health multiplier; `IncreasedMaxHealthMultiplier` | root / FloatProperty / dimensionless multiplier | `{domainId, scopeRef:"source"}`; `enchanted-grass:configured-max-health-multiplier@1` | none | known 1; other domains not-applicable |

Each field needs one exact root CDO locator from the census and a source-backed `SourceBackedValue`; any missing or undecoded occurrence becomes `unavailable` with its actual Raw state, never numeric zero. These three are **design-ready**, while current v2 directly populates **0/23** because the Artifact lane does not exist. The remaining 20 lack these narrow semantics; the other decoded scalars need unit/meaning review or are one-off implementation configuration. `StunDuration` has a duration name but no source-established unit, and `Damage`, `baseDamage`, `DamagePerMine`, `ShockwaveDamage`, `EffectRange`, `SpawnDelayRange*`, `aimingTime`, and `laserTime` must remain separate candidates. Configured duration/damage/healing and effective duration/damage/healing are distinct contracts.

Classification: `Effect` is a stable configured gameplay effect link and uses existing `RelationKind = effect`. `ItemActorClass` is a gameplay-relevant linked actor class, but `gear-actor` names an Armor relation and should not be repurposed; a future `item-actor` or `artifact-actor` semantic kind needs a reviewed definition. The one explicit `ClassesToSpawn[0]` is a spawn-class relation; existing ranged `projectile` denotes a configured shot projectile and should not be assumed equivalent. Other class fields (`BeesNestClass`, `FishingHookActorClass`, `FishingRodActorClass`, `ChargedRedstoneMineBP`, `MobMashShockWave*`, `SpinWheelActorClass`, `TotemClass`, `CustomMover`) need per-family semantics and target review. `ActivationAnimation`, Montage, fish-hook animation, LandingEffect particle, audio, `Paperdoll`, UIData/iconClass are presentation. `RootComponent`, generic component wiring, import/class/outer, `super` and `template` are structural plumbing. Native `TypeHierarchy[*].classType` is a native boundary. Harpoon Quiver has no root gameplay edge in this closure; absence is not a zero effect.

For a single root `Effect`, `{domainId, scopeRef:"source"}` is the stable occurrence. There is exactly one per selected domain, so no `collectionRef` or `sourceIndex` is justified. Generalize the existing Armor scope source resolver's exact Identity package, Horizontal edge ID, Structural shard/hash, and target checks into a shared scope helper, then add a strict Artifact `Effect` policy (`propertyPath === "Effect"`, `relationKind === "object-property"`, local GameplayEffect target). Do not directly route Artifact through the Armor `GearActor` branch. Existing `RelationKind = effect` and Relation v2 scope schema suffice for this wave; audit/integration fixtures and expected counts need updating. A later `ItemActorClass` wave needs a new stable kind and adapter; `TomeActorClass` has no population candidate.
