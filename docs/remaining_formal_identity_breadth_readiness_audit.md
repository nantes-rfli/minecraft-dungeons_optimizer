## Current authority and decision rule

The primary current inputs are `research/domain/formal/identity-evidence-v1.json`, `src/domain/formal/identityDefinitions.ts`, `research/domain/game-data-entity-aliases.json`, `scripts/equipment-icons.ts`, `research/raw/game-data-raw-structural-inventory/manifest.json`, current category audit/catalog sources, and the current Formal Identity inventory/source-grounding scripts.

A unique Raw candidate is **not** treated as a canonical bridge. `ready-*` requires an explicit current source chain to the canonical catalog identity. Fuzzy/display-name similarity, path similarity, icon ordinal ordering, and uniqueness by themselves are never used to promote an identity.

The existing `scripts/formal-identity-inventory-source.ts` adapter is category-neutral: once a Formal definition supplies an application-scope package, it resolves that package from the Raw Structural Inventory and reads `ItemIdName` / `ItemId.SerializedId`. This is why the 70 Armor records below are adapter-ready rather than requiring a new identity semantic.

## Repository-wide bridge discovery

1. **Accepted/high Artifact aliases already committed — 6.** These six records are directly analogous to the current Death Cap Mushroom identity path: reviewed alias → canonical artifact ID, exact Raw package in `assetPaths`, decoded serialized identity in the structural inventory.
2. **Armor catalog internal IDs — 70.** `research/armor-audit.json` commits canonical armor ID → `levelId`. For all 70 adapter-ready Armor domains, both decoded `ItemIdName` and `ItemId.SerializedId` equal that `levelId`, and the manifest records `serialized-catalog-identifier-match`. This is stronger than name/path inference and does not need an alias promotion.
3. **Artifact exact serialized-ID bridge candidates — 22.** These are not promoted directly because no accepted/high reviewed alias is currently committed. The Raw Structural Inventory records decoded serialized identity plus `serialized-catalog-identifier-match`, with the canonical artifact/category supplied by the current artifact catalog. The same evidence form already appears in accepted/high Artifact alias records, so a bounded reviewed-alias bridge is feasible.
4. **Documented Artifact overrides — 15.** `scripts/equipment-icons.ts::ENTITY_OVERRIDES` explicitly maps canonical artifact IDs to Raw internal identities for these records, and current Raw observations corroborate those identities. Unlike the three already-reviewed weapon overrides, these artifact mappings have not yet been materialized as accepted/high aliases; they therefore remain small reviewed-bridge work.
5. No additional ready Melee/Ranged bridge was found. Their one-candidate cases retain decoded Raw identities but lack a current accepted/high alias or another explicit canonical bridge; their multi-candidate cases stay ambiguous.

Generated artifacts were not double-counted as independent evidence. Where a generated/current inventory records a match, this audit points back to the hand-authored catalog/override or reviewed alias that gives the canonical bridge.
