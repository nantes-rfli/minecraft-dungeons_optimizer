# Artifact reviewed-bridge identity adjudication audit

## Scope and baseline

- Baseline: `origin/main` at `85e2a354eef06ee8fa3649e1b598f677f7dc67e0` (2026-09-26).
- Scope: the 37 Artifact IDs in `docs/remaining_formal_identity_breadth_readiness_audit.md` under `ready-with-small-reviewed-bridge`. That earlier classification is an input set, not the decision here.
- This is evidence adjudication only. No Formal definitions, aliases, Raw extraction, schemas, generated artifacts, or runtime code were changed.
- Current Formal population at baseline: 128/271 total; Artifact 7/45.

## Decision rule and evidence authority

- `research/artifact-audit.json` supplies the canonical Artifact `id` and display name. It does **not** contain a Raw internal identity for these 37 records.
- `scripts/equipment-icons.ts::ENTITY_OVERRIDES` is a hand-authored canonical Artifact ID → Raw identity mapping. For this adjudication it is usable bridge evidence only when its string equals both values decoded from the exact candidate Structural package.
- The committed Structural manifest supplies current candidate status, count, role, package and search basis. Each reported `ItemIdName` and `ItemId.SerializedId` was independently read from the candidate package in the named compressed Structural shard, at the class default object. A manifest evidence string alone was not substituted for this check.
- `serialized-catalog-identifier-match` in the manifest is generated by `scripts/game-data-raw-structural-inventory.ts::resolveRawSeedCandidates`: it compares normalized catalog ID / internal ID tokens with decoded serialized values. Artifact catalog entries have no `internalId`. Thus, for the 22 S rows, the manifest match plus catalog display name is a derived slug comparison, not an independently committed canonical→Raw bridge. The icon manifest is a presentation/search hint only.
- Accepted/high Formal source grounding currently requires a reviewed alias at `research/domain/game-data-entity-aliases.json` with the exact canonical entity, Raw identity, package and status. None of these 37 has such an accepted/high alias. The 12 O1 rows have sufficient source evidence to create that reviewed alias; direct Formal population before its materialization would fail the established source-grounding contract.
- An override differing only by letter case is not assumed equal to a serialized identifier. Variant suffix, family, package path, candidate uniqueness and icon output were not used as identity bridges.

Legend: S = decoded serialized ID / generated exact catalog match; O = documented override. `n/a` in the equality column means no independent bridge asserted a Raw identity. Reason codes: **O1** = explicit override equals both Structural fields; reviewed accepted/high alias and Formal source record still need materialization. **O2** = override differs from both Structural fields in case; resolve the conflicting spelling before alias review. **S1** = decoded fields and generated exact match exist, but no independent source explicitly links canonical domain to Raw identity.
